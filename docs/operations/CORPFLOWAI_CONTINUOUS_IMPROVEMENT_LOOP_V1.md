# CorpFlowAI Continuous Improvement Loop v1

Authority: #1381, extending #1370 and #1372.

## Objective

Make CorpFlowAI improve from verified experience without creating another platform, database or autonomous-risk surface.

Operating loop:

`observe -> execute -> verify -> learn -> promote -> re-route -> replay`

## Completion improvement contract

Every governed ChatGPT, Cursor or Forge completion must end with a compact improvement result:

- what changed;
- verification result;
- correction/failure if material;
- reusable lesson candidate;
- routing implication;
- durable source updated;
- supersession candidate;
- or explicit `NO_MATERIAL_LEARNING`.

Do not manufacture a lesson merely because a task completed.

## Promotion ladder

`OBSERVATION -> CANDIDATE -> VERIFIED -> ADOPTED -> SUPERSEDED`

Automatic promotion is allowed only for low-risk deterministic learning with repeated passing evidence.

Architecture, security, production, financial-policy, commercial and client-commitment learning requires review before adoption.

Contradictory evidence does not silently overwrite existing learning. It remains a candidate/dispute until resolved or superseded.

## Adaptive routing

The router may recommend the cheapest proven executor from evidence:

1. deterministic automation where a rule-based path has enough successful samples;
2. Forge when bounded task PASS/rework/escalation economics are acceptable;
3. Cursor where lower-tier evidence is absent or rework/failure is too high;
4. higher-cost paths only when separately justified.

Routing recommendations never bypass protected-action approval.

## Replay suite

`fixtures/learning/corpflow-replay-suite-v1.json` is the initial organisational regression corpus.

It contains paid-for lessons and failure modes that future agent/runtime/router changes must continue to respect.

Add a replay case when a material incident, correction or supersession creates a reusable regression condition.

## Freshness and contradiction

State-changing work must reconcile canonical docs and active learning records when it installs, removes, renames, activates, retires or supersedes:

- runtimes;
- executors;
- providers;
- architecture rules;
- client operating commitments;
- source-of-truth rules.

A durable issue is not sufficient if the canonical bootstrap can still return a contradictory current answer.

## Business success measures

Self-improvement is useful only when it improves at least one measurable outcome:

- fewer Anton interventions;
- lower Cursor spend;
- faster verified delivery;
- fewer repeated defects;
- higher Forge acceptance;
- lower rework/escalation;
- faster client conversion/delivery;
- better gross margin;
- more verified client/revenue output per total execution cost and elapsed time.

If an improvement mechanism cannot show value, do not expand it.

## Protected boundaries

This loop may observe, propose, record, test and recommend inside existing approved boundaries.

It may not autonomously perform production deploys, production DB/schema/data changes, env/secrets/access changes, payments, external messages/publishing, paid-tool actions or public/client launches.
